# 23 GC：分代 + 并发三色标记

无引用计数（无循环问题、无延迟释放）；追踪式，Go 风格并发化 + 分代提速知暂对象。

## 1. 堆布局

```
┌──────────────── heap ────────────────────────────────┐
│ young: 每 worker 一对 semispace（各 256KB 起步）     │
│ old:   block 链表（128KB/块，bump 分配）             │
│ large: > 32KB 直接 old 独立块（不复制）              │
│ 永久:  intern 字符串/代码对象/内置类（不回收）       │
└──────────────────────────────────────────────────────┘
```

- 新对象一律 young bump 分配（指针递增，仅 young 顶点越界检查）。
- 存活 2 次 minor GC 晋升 old；年龄存对象头 flags。

## 2. 触发

| GC | 触发条件 |
|----|----------|
| minor | young 半空间满 |
| major（并发标记） | old 活跃估算 ≥ 堆目标（heapGoal = 存活×2.0，可调） |
| 强制 full | `runtime.gc()` / 内存压力兜底 |

## 3. minor GC（young，复制式）

- Cheney 半空间复制：roots + 记忆集（old→young 引用，见 §5）出发，广度扫描复制存活对象到 to-space，年龄 +1，达 2 晋升 old。
- **STW** 执行（young 小、目标暂停 < 1ms；256KB 复制上限可控）。
- 晋升 old 时经写屏障保障并发标记一致（§6）。

## 4. major GC（old，并发三色）

```
1. mark setup（STW #1，µs 级）
   开写屏障 → 扫描固定 roots（全局表/内置/各 worker 栈寄存器快照）
   → 根置灰入队 → 唤醒标记线程 → 恢复 mutator
2. concurrent mark（并发）
   GC 线程 drains gray 队列；worker 线程 assist（配额比例）
   新分配对象直接置黑（分配即黑，免再访）
3. mark termination（STW #2）
   排空残余灰 → 关闭写屏障 → 本轮存活统计 → 唤醒清扫
4. concurrent sweep（并发/增量）
   old 块逐块回收白对象（free-list 归还块）；mutator 分配时惰性 assist
```

- 写屏障：**混合屏障**（Go 1.8+ 方案）——

```
写入 oldobj.field = newobj 时（且本轮标记激活）：
  if oldobj 是灰色: shade(newobj)          // Dijkstra 插入
  shade(旧值 oldobj.field 之前的对象)       // Yuasa 删除
```

- 删除屏障保证被覆盖引用不失联；插入屏障保证新引用可见；组合后 **STW 重扫栈可避免**（栈帧在 STW #2 内统一保守按灰处理一次，量小）。

## 5. 跨代引用（记忆集）

- old→young：**card marking**——old 块按 512B 分 card，写屏障将 oldobj 所在 card 标脏；minor GC 只扫描脏 card。
- 并发标记期间 card 表同时服务两用途（脏 card 亦作为 old 侧标记根补充）。

## 6. safepoint 与握手

- `CHECK_SAFEPOINT`（`21-bytecode.md` §6）递减预算；预算尽 → 检查全局 GC 状态字（atomic）。
- mark setup：置全局标志，各 worker 在下一检查点自旋等待并交出栈快照（精确栈图：frame map 记录每帧哪些槽是 MsValue；compiled chunk 内建 map）。
- C 栈非精确部分（嵌入调用链上的 handle）由 handle 注册表覆盖（`25-capi.md`）。

## 7. 特殊对象

- WeakRef：标记结束后，白名单弱表节点 `get()` 置 nil；弱节点本身黑色保活。
- Channel/COROUTINE/FUTURE：Coroutine 栈整体作为 root（活跃 G）；parked 的 G 由调度器持有引用。
- Module：永久代（脚本运行期模块不卸载，v1 简化）。
- big 分配（>32KB）：不复制，minor 时标记存活直接留 old。

## 8. mutator assist

- major 期间每个 worker 按分配量分摊标记配额（`assistBytes` 比例）；防止分配速度 > 标记速度导致堆失控。
- 堆硬上限（默认 4GB，`MS_GC_HEAP_MAX`）：触顶 → full GC + OOMError。

## 9. 参数与环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `MS_GC_HEAP_MAX` | 4G | 硬上限 |
| `MS_GC_GOAL` | 2.0 | heapGoal 倍率 |
| `MS_GC_YOUNG_KB` | 256×N | young 初始（每 worker 一份 nursery） |

- `runtime.gcStats()`：暂停分位数、次数、存活字节、assist 时间。

## 10. v1 线程模型

- N 个 worker（mutator）+ 1 个 GC 标记线程；minor 在各 worker 各自 nursery 上独立 STW（局部停顿，不全局冻结——worker 间无共享 young 区）。
- 后续可扩展：标记并行化（多 GC 线程分块标记）。

## 11. 明确不做

- `__del__` 终结器（ defer + WeakRef 覆盖；Python 之坑）。
- 压缩 old 区（标记清除 + 空闲列表；碎片依赖大对象独立块缓解）。
- 移动式 old / 读屏障（无）。
